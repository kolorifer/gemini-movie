## Keep / Drop / Invariants — movie-intel handover

**Production baseline, 25 November 2026.** I checked the seedbox actor at `89e7f99`. It already evaluates unidentified releases, sends torrent evidence, and offers two rated Watched choices. Two important gaps for the rewrite are durable burst deduplication and notification suppression. The legacy actor archives duplicate deliveries separately, can still annotate an existing or watched movie, and can skip enrichment for a routine rejection yet still send a card. Do not use the number of legacy Telegram sends as the shadow acceptance criterion.

### Keep — intake to card

1. **Receive and acknowledge.** Authenticate the autobrr webhook. Preserve every complete valid JSON delivery, including duplicates and non-movie events, in the existing private raw archive before business filtering. An archive occurrence, a release and a Telegram action are three different identities. For the movie lane, inspect `action.rejected`, `data.result.rejections` and `data.release` (type, title, year, exact name), plus `data.indexer`. A movie category with a conflicting release type warrants a diagnostic only. Announce, IRC, feed and housekeeping events must not start an assessment or acquisition.
2. **Coalesce work.** In the rewrite, atomically claim one assessment/card for duplicate bursts, including concurrent deliveries 2–8 seconds apart. Correlate source, tracker release ID and exact release; retain the delivery IDs separately. Do not collapse two encodes, editions or trackers because their title/year or IMDb ID matches. A later correction to the same occurrence should update or supersede its card. Test restart and late delivery as well as simultaneous arrivals.
3. **Enrich and evaluate.** Treat autobrr `meta_imdb` and `meta_tmdb` as hints; `external_id` identifies the tracker release. Use the exact TorrentLeech listing when appropriate. POST the original release name as `raw_text`, optional title/year hints, and available `torrent_info` to the local evaluator. Send observed IDs, indexer/category, technical quality, actual file runtime/audio, decimal GB, freeleech (including false), and sanitized description/NFO. Omit unknowns. Keep audio distinct from subtitles and file runtime distinct from catalogue runtime. Respect quality-specific cache identity; bypass a cached result if its key cannot distinguish changed evidence.
4. **Identify and present.** Send unresolved movies to the evaluator too. Use its returned title, year, IDs, confidence and explanation. A high-confidence proposal gets ordinary action links only after independent title/year, IMDb↔TMDb movie, source/runtime and local conflict checks pass. Otherwise offer evidence review. A WATCH verdict is a recommendation, never an acquisition instruction. Deliver the card promptly and return the evaluation or redacted error as a reply to its acknowledged message and topic. A newer verified correction wins.
5. **Suppress before delivery.** For the rewrite, suppress routine acquisition prompts for an exact watched/unmonitored match and routine already-owned, quality-rejected or non-upgrade releases. An existing monitored entry can lack a file; monitoring alone proves neither ownership nor viewing. Distinguish that case from an existing file, an explicitly supported alternative edition, and a genuine identity conflict. A stale/ambiguous Radarr lookup does not establish absence. Older actors’ generic passthrough messages are not required movie cards.

### Keep — Telegram decisions

| Confirmed choice | Radarr operation | Evaluator feedback |
|---|---|---|
| Add & Grab | Validate the selected root/profile against current Radarr choices. Look up by exact TMDb ID; reuse an existing movie, or add it monitored with search disabled. Push **only the announced release** to `/api/v3/release/push`. Require one decision with `approved=true` and `rejected=false`; HTTP 200 alone is insufficient. | After acceptance, POST the actual title, IMDb and TMDb IDs, `decision=watch`, `note=Grabbed via Telegram`. |
| Add as watched – Good / Bad | Add unmonitored or update the exact existing movie. Add the `watched` tag, preserve files and other tags, and read back both tag and monitoring state. No search or push. | Good → `watch`; Bad → `skip`; both use `note=watched`. Report a saved rating only on the evaluator’s matching saved acknowledgment. Older unrated links do not imply a rating. |
| Standalone Skip (optional new feature) | No Radarr change. **Watched – Bad is a different decision:** the user has seen that movie. | Explicit user choice → `skip`. Do not synthesize a skip from ignoring a card. |

**Alternative Grab** is a separately configured, explicitly confirmed quality-only exception. If retained, bind it to the exact existing movie/file, original release and allowed rejection class, then revalidate at confirmation. Never convert an identity conflict into “Grab Anyway.”

### Invariants — release blockers

- **Tracker access.** Use the dedicated owner-only regular cookie file; reject symlinks and unsafe permissions. Allow only the canonical HTTPS TorrentLeech numeric listing route; never fetch the download URL for identification. Check for login HTML even on HTTP 200. All release headings must match the announcement after whitespace normalization and removal of the known freeleech badge. Missing, malformed or conflicting IMDb fields/links are distinct outcomes. Serialize listing requests, bound body size and time, honor cooldowns and `Retry-After`. A failed lookup cannot authorize a title-only guess.
- **Actions and delivery.** GET opens a private confirmation; only an explicit POST may mutate Radarr. Bind expiring opaque tokens to the release, movie and permitted action. Serialize concurrent submissions, persist the attempt before external writes, and reconcile ambiguous outcomes before another attempt. Good/Bad share one watched completion. A feedback failure must not repeat or undo a successful Radarr action. A lost Telegram acknowledgment is also ambiguous: bind edits/replies to the returned chat, message and topic; never guess a destination or resend a possibly delivered grab card.
- **Telegram limits.** Escape untrusted HTML. Budget for 1,024-character captions and 4,096-character text messages, including non-BMP text. Fall back from poster to text, keep buttons on the actionable card, and attach long evaluation details as a private text file. A poster failure must not queue a second evaluation.
- **Privacy and replay.** Keep exact raw inputs owner-private (directories 0700, files 0600). Resolve the original release privately for a confirmed push. Never copy download URLs, passkeys, cookies, webhook/action tokens or API credentials into model prompts, ordinary SQLite records, logs, examples or GitHub. Strip secret-bearing URLs from errors too. Shadow replay uses sanitized inputs and stubbed Telegram, feedback and Radarr writers; it must produce zero external mutations.

### Drop from the new services

Leave festival rankings, scoring simulations/calibration, festival feed generation, GitHub governance/dispatch, library-wide import/sync, watched-list imports and bulk tagging in their existing projects. Do not port the research scanner/provider/sandbox, identity-triage sidecar and socket, historical handoff queues, supervised credit/Keychain pilots, one-event capture harnesses, audit ledgers or Mac-dependent assessment worker. Examples include `identity-investigation-scan.timer`, `identity-research.service`, `identity-triage.{socket,service}`, and `movie-list-sync.timer`. Preserve their history in place. The replacement still needs small durable records for occurrence deduplication, action state and delivery receipts. This list is a migration boundary, not an instruction to disable existing units.

- **Intake and proxy:** `MOVIE_INTEL_HOST`, `MOVIE_INTEL_PORT`, `MOVIE_INTEL_WEBHOOK_SECRET`, `MOVIE_INTEL_PUBLIC_BASE_URL`. The public HTTPS action origin comes from configuration.
